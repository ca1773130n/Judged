# What Gate 2 is worth: the veto measured against the E2 catalogue

**Date:** 2026-08-02 · **Tools:** vulture 2.16, knip 6.31.0, `x/tools` deadcode v0.48.0,
cargo-shear 1.13.3, git 2.50.1, node v24.14.0 · **Gate 2 configuration:** gates
`literal, reachability`, needles `basename+stem` (the shipped default)

> **This evaluation is IN-SAMPLE, and that is the first thing to know about every number
> in it.** Gate 2's rescue vocabulary and the 19 mutant classes come from the same
> document. §10 E2 specifies the classes; §6.12, §6.2, §5.2 and §6.11 specify the
> reference shapes, and those are the sections the veto was written from — the
> `ENUMERATION_CONSTRUCTS` list in `judged-core/src/veto/reachability.rs` cites §6.12 and
> §5.2 by name, and the fixtures plant `dir.glob`, `readdir` and `include_str!`, all three
> of which are on that list. The gate is being graded on the exam it studied for. Read
> every prevention figure below as an **upper bound** on what the same gate would do
> against a repository nobody wrote a fixture for.

**Result: of the ten false removals four off-the-shelf analyzers commit unprotected, Gate 2
prevents four, at a cost of seven of their twenty-six recovered decoys. Three of the seven
affected classes are cleared; four still remove something live. No configuration measured
here takes an analyzer from a non-zero false-removal count to zero without also taking its
decoy recall to zero: the one that manages the first half — knip at the widest needle
strategy — finds 0 of 6 decoys doing it.**

The six that survive are the interesting half. Five of them — `ReportingConfig`, three
reflection-touched model fields and a `//export`ed ABI symbol — leave **no literal trace
anywhere outside the file that declares them**. A whole-repo literal search cannot rescue
what is not written down twice, and no needle setting changes that: it is a structural
ceiling on Gate 2a rather than a tuning problem. The sixth is reached by an import specifier
assembled at runtime, and only the directory needle finds it, at the price section 7
measures.

## 1. Reproducing this

Every figure below is read out of `--json`, and every derivation is a sum over named fields
so a reader can redo it without trusting a script. Per-run totals come from
`veto.false_removals_prevented`, `.false_removals_remaining`, `.decoys_found_bare`,
`.decoys_found_gated`, `.decoys_lost`, `.claims_judged` and `.claims_blocked`; per-claim
evidence comes from `mutants[].veto.blocked_claims[]`, whose `needle`, `needle_kind`,
`found_in`, `declared_in` and `detail` are quoted verbatim. Aggregates over the four
analyzers are plain addition across their four reports, with the one exception section 2
names.

| Tool | Version | How it was obtained |
| --- | --- | --- |
| vulture | `2.16` | `uv venv` + `uv pip install vulture` in a throwaway directory outside the repo, removed afterwards |
| knip | `6.31.0` | `npx --yes knip@6`, node v24.14.0 |
| deadcode | `golang.org/x/tools v0.48.0` | `~/go/bin/deadcode` |
| cargo-shear | `1.13.3` | built from source outside the repo |
| git | `2.50.1` | the corpus enumerator: Gate 2a reads `git ls-files -s -z` |

```sh
# Sections 2 and 3: every SUT, bare and gated, at the shipped configuration.
for sut in naive refusing vulture knip deadcode shear; do
  judged mutants --sut $sut          --json > $sut.bare.json
  judged mutants --sut $sut --veto   --json > $sut.veto.json
done

# Section 7: the §11 R8 needle sweep. `--needles` did not exist when the superseded
# round published its sweep, which is why that sweep is gone rather than corrected.
for sut in vulture knip deadcode shear naive; do
  for n in basename basename+stem basename+stem+parent-dir basename+stem+parent-dir+symbol; do
    judged mutants --sut $sut --veto --needles "$n" --json > $sut.$n.json
  done
done
```

`--veto` runs the suite a second time with §9.3's Gate 2 wrapped around the same analyzer
and reports the difference. Two runs rather than one, because "how many false removals did
the veto prevent" is a question about a pair of runs; deriving it from a single run would
mean assuming the answer.

Gate 2 as configured here:

- **2a, the whole-repo literal search.** Structurally mandatory — `GateSet` has no field for
  it and no constructor can remove it. Needles `basename+stem` (`DEFAULT_NEEDLES`).
- **2b/2c, reachability.** A manifest names the path, or something enumerates its directory
  at runtime.
- **2e, recency: OFF.** Every fixture repository is created, written and committed seconds
  before the analyzer is spawned, so the newest commit touching any path is always inside
  any window and 2e would rescue every claim in every class. That is a true answer about a
  scratch directory and no answer at all about a tool.

A veto can only rescue. `mutants_cmd::compare` refuses to publish a report whose gated
false-removal **set** is not a subset of the bare one, and refuses one whose gated decoy
count is higher. Every run below published, so in no run did the veto layer cause a
candidate to be claimed dead.

Seven classes. Per claim: whether Gate 2 prevented it, on which needle, in which file, and
whether that file is a different file from the one the analyzer said declares the symbol.
Taken from `--veto --json`; `declared_in` and `found_in` are adjacent fields in every
`blocked_claims` entry.

| m01 | vulture: `DunningConfig` | **yes** | `DunningConfig` (symbol) | `ledger/dunning.py` | `ledger/apps.yaml` | yes |
| m02 | knip: `src/transports/websocketTransport.ts` | no | — | — | — | — |
| m10 | vulture: `ReportingConfig` | no | — | — | — | — |
| m11 | vulture: `tenant_slug` | no | — | — | — | — |
| m11 | vulture: `retention_days` | no | — | — | — | — |
| m11 | vulture: `legal_hold_until` | no | — | — | — | — |
| m12 | deadcode: `drain` | **yes** | `drain` (symbol) | `internal/sampler/drain.go` | `internal/collector/collector.go` | yes |
| m12 | deadcode: `TelemetryFlush` | no | — | — | — | — |
| m14 | knip: `dist/widget.7f3a91c.js` | **yes** | `widget.7f3a91c.js` (basename) | — (path claim) | `public/index.html` | yes |
| m16 | vulture: `RateSnapshot` | **yes** | `RateSnapshot` (symbol) | `pricing/legacy_rates.py` | `var/cache/quote-cache.pkl` | yes |

**Four prevented, all four cross-file. No self-reference rescues remain, anywhere in the
run.** Across all four analyzers Gate 2 blocked 15 claims at the shipped configuration, and
in every one of them `declared_in` differs from `found_in` or the claim was a path (whose
own file Gate 2a has always excluded). That is the direct measurement of the defect section 6
describes: before provenance reached the gate, every symbol claim was rescued by its own
declaration.

The three cleared classes are m01, m14 and m16. m12 is half cleared: `drain` is rescued and
`TelemetryFlush` is not.

- **m01 — `DunningConfig` in `ledger/apps.yaml`, byte 352.** A Django `AppConfig` named only
  as a dotted string in a YAML app list. The clearest symbol rescue in the suite: another
  file, a different format, the exact spelling.
- **m12 `drain` — `internal/collector/collector.go`.** The needle fires inside the
  `//go:linkname drainSamples …sampler.drain` comment. A comment is not a call, which is the
  point: deadcode's call graph is right and its conclusion is wrong, and the literal search
  sees what the call graph structurally cannot.
- **m14 — `widget.7f3a91c.js` in `public/index.html`, byte 318.** A path claim, its own file
  excluded from the corpus from the start, evidence in an unrelated file. Checked-in build
  output whose only consumer is a CDN path.
- **m16 — `RateSnapshot` in `var/cache/quote-cache.pkl`, byte 36.** Gate 2a searches every
  file `git ls-files` reports, including binaries, so a class name inside a pickled cache
  entry is found. Section 8 records what that property costs.

### Why the other six survive, and why no needle setting fixes it

None of the six leaves a literal trace the shipped needle set can find outside the file it
lives in.

- **m10 `ReportingConfig`** — the fixture states it outright: *"the string `ReportingConfig`
  occurs in this file and in no other."* Django finds the class by convention from the
  module path; the class name is never spelled by the framework.
- **m11 `tenant_slug`, `retention_days`, `legal_hold_until`** — model fields reached by a
  serializer that walks `type(model).model_fields` and pulls each value with `getattr`.
  §6.1 predicts this one by name: structural reflection *"defeats even the grep veto — there
  is no identifier string anywhere to match, because the reflection is over shape, not
  name."* That prediction is now measured, and it holds.
- **m12 `TelemetryFlush`** — `//export TelemetryFlush` and the function declaration are both
  in `cmd/libtelemetry/abi.go`. The consumer is a C agent that `dlopen`s the shared library,
  which is outside the repository by construction. This is E2 class 19's shape and it is
  *designed* to be unfalsifiable from inside the repository.
- **m02 `src/transports/websocketTransport.ts`** — reached by
  `` await import(`./transports/${kind}Transport.js`) ``. The specifier is assembled at
  runtime and exists as a contiguous literal nowhere.

Gate 2a excludes the declaring file and asks whether anything **else** names the artifact.
When the honest answer is *no*, there is nothing for the gate to do. Widening the needles
does not create evidence; section 7 shows the one case where widening reaches m02, and what it
costs.

| --- | --- | --- | --- |
| vulture 2.16 | 2 of 6 | 1 of 11 found | 4 live artifacts still removed, 10/16 recall kept |
| knip 6.31.0 | 1 of 2 | 2 of 4 found | still fails m02, half the recall |
| deadcode v0.48.0 | 1 of 2 | 0 of 2 found | the only free rescue in the table |

Where the seven lost decoys went, from the same `blocked_claims` records:

- **cargo-shear, 4 — all to the reachability gate, none to a needle.** Two runtime
  enumerations in `src/lib.rs`, a `readdir` and an `include_str!`, root the directories those
  files sit in, so `src/orphan_glob_cache.rs`, `src/unused_depth_limit.rs`,

  needle strategy, because it is not a needle. cargo-shear was already at zero false
  removals with 9/9 recall, so Gate 2 could not improve the numerator and took four off the
  denominator.
- **knip, 2 — also reachability.** `tsconfig.json`'s `/**` roots the tree, rescuing
  `dist/widget.0c9e142.js` and `src/unusedFeatureFlags.ts`.
- **vulture, 1 — the literal gate, on a needle that means nothing.** The claim is the symbol
  `export`, declared in `app/legacy_metrics_export.py`. The report's own line, verbatim:

  ```
  [literal] blocked symbol export (declared in app/legacy_metrics_export.py) — android/app/src/main/AndroidManifest.xml names it: the symbol needle "export" occurs at byte 503
  ```

  `app/legacy_metrics_export.py` is a genuinely dead file. The word `export` appears in an
  Android manifest, as it appears in almost any XML.

That last one generalises, and it is the failure mode this round exposes now that the
self-rescue is gone. Four of vulture's seven blocked claims are rescued by a **generic
identifier colliding somewhere unrelated**: the symbol `name` three times (found in
`ledger/legacy_invoice_dump.py`, `package.json` and `pyproject.toml`), and `export` once. A
symbol needle is only as good as the symbol is distinctive, and analyzers that report every
unused local name produce claims like `name` all day. The fix that made the gate measurable
did not make it precise; it moved the imprecision from *every symbol* to *every common
word*, which is a smaller set and still not a small one.

## 6. The self-veto defect, as a finding in its own right

This is a finding about the design of vetoes, not a changelog entry, and it is the reason
the previous round's gated numbers were withdrawn rather than adjusted.

`SutVerdict::claimed_dead_symbols` was a `Vec<String>`: bare names, no provenance. Gate 2a
excludes a candidate's own file from the corpus before searching, because a declaration is
not a reference to itself. For a path claim the file to exclude *is* the claim. For a symbol
claim it is the file that declares the symbol — and a bare name cannot say which file that
is, so the harness passed `UNKNOWN_DEFINING_FILE`, the empty path, which matches no tracked
file. Nothing was excluded. Every symbol was found in its own declaration. Every symbol
claim was rescued.

The measured consequence: vulture went from 11 of 16 decoys to **0 of 16**, deadcode from 2
of 2 to **0 of 2**, and both printed `false removals: 0 — GATE PASSED`. They cleared the
release gate by claiming nothing at all.

Three things about it are worth keeping.

**A veto that fires on every input is a constant function, and a constant function measures
nothing.** The code documented the empty path as "the conservative direction", and that was
true and irrelevant. Excluding nothing can only produce more rescues, never fewer, so it is
safe — but §3.7 already makes the corresponding argument about positive controls: a control
that always passes is theatre. It holds for a gate the same way. Safety is not the question
when the alternative is a function with one output.

**The information was never missing.** All four adapters already parsed the location and
threw it away: vulture prints `path:line: unused ...`, deadcode carries a `Position`, knip
carries an artifact `uri`. Only the type lost it. The defect was one field wide.

**It passed a full review because the report could not show it.** `--veto --json` emitted
`found_in` and nothing else, so a genuine cross-file rescue and a symbol rescued by its own
declaration printed the identical shape — a plausible file name beside a plausible needle.
Four rescues from the superseded build, with the annotation the report did not carry:

```
RATES          found_in=ledger/unused_currency_table.py     <- declares RATES
dump_invoices  found_in=ledger/legacy_invoice_dump.py       <- declares dump_invoices
hang_indent    found_in=pluginhost/textwrap_helper.py       <- declares hang_indent
MIDDLEWARE     found_in=ledger/settings.py                  <- declares MIDDLEWARE
```

(That block is the only quotation in this document that does not come from the current
build. It cannot: the CLI now always passes the declaration site when the analyzer gave one,
so those four lines are no longer producible.)

Nothing in the output was wrong. Every line was a true statement about where a string was
found. The `<-` column is what the reader had to supply from memory to see that `found_in`
was the declaring file every time, and no reader has that. The decoy column went to zero in
the same run, and was read as the veto being expensive rather than as the veto being broken.

The report now emits `declared_in` beside `found_in`, and
`mutants_cmd::a_blocked_symbol_shows_its_declaration_site_beside_the_evidence` pins it. The
degenerate case still exists — an analyzer that names no file gets `UNKNOWN_DEFINING_FILE`
and is rescued by its own declaration, correctly, since there is genuinely nothing to
exclude — and
`judged-mutants/tests/veto_gate.rs::an_unattributed_decoy_symbol_is_rescued_by_its_own_declaration_and_that_is_the_documented_cost`
pins that as a cost rather than a property.

The generalisable rule: **a report that cannot distinguish evidence from tautology will be
read as evidence.** An output field is not documentation, it is the only place a reviewer
can catch this class of error, and "the number moved in the direction I expected" is how it
gets past them.

## 7. §11 R8: the needle-strategy sweep

R8 records two requirements that conflict — §9.3 says *block on any hit*, a usable tool
needs a tolerable flag rate — and asks for a measurement rather than an argument. It also
states its own acceptance criterion: *"pick the strategy where fire rate is tolerable and
the E2 string-reference mutants (classes 1, 8, 13) still all get caught."*

**The superseded round's sweep is deleted rather than corrected, because it was not
reproducible.** It cited `VetoedSut::with_needles`, which existed but which no command line
reached, so no reader could re-derive a single row. `--needles` now exists; the sweep below
is the second loop in section 1, and the strategy each row was run under is echoed back in that
run's own `veto.needles` field.

Aggregated over the four real analyzers, gates `literal, reachability`:

| Needle strategy | FR prevented | FR remaining | decoys gated | fire rate |
| --- | --- | --- | --- | --- |
| `basename` | 4 / 10 | 6 | 19 / 29 | 15/58 = 26% |
| `basename+stem` *(shipped)* | 4 / 10 | 6 | 19 / 29 | 15/58 = 26% |
| `basename+stem+parent-dir` | **5 / 10** | 5 | 17 / 29 | 18/58 = 31% |
| `basename+stem+parent-dir+symbol` | **5 / 10** | 5 | 17 / 29 | 18/58 = 31% |

Per SUT, so the aggregate cannot hide which tool moved:

| SUT | strategy | prevented | remaining | decoys gated | fire rate |
| --- | --- | --- | --- | --- | --- |
| vulture | all four | 2 | 4 | 10/16 | 7/37 = 19% |
| deadcode | all four | 1 | 1 | 2/2 | 1/6 = 17% |
| cargo-shear | all four | 0 | 0 | 5/9 | 4/9 = 44% |
| knip | `basename`, `+stem` | 1 | 1 | 2/6 | 3/6 = 50% |
| knip | `+parent-dir`, `+symbol` | 2 | 0 | **0/6** | 6/6 = 100% |
| naive | `basename` | 9 | 11 | 26/31 | 25/130 = 19% |
| naive | `+stem` | 13 | 7 | 26/31 | 29/130 = 22% |
| naive | `+parent-dir`, `+symbol` | 16 | 4 | 18/31 | 57/130 = 44% |

Four things fall out.

**`+symbol` is not a fourth data point.** It is identical to `+parent-dir` in every cell.
The symbol needle derives from a *candidate's* symbol name; a path candidate has none, and a
symbol candidate is judged by `VetoedSut::symbol_needles`, a fixed strategy (`BASENAME_ONLY`
plus `Symbol`) that this flag does not reach. R8's four-way sweep is a three-way sweep in
this build. Stated as a limit rather than buried: **the sweep moves path claims only**, and
43 of the 58 claims here are symbols.

**`basename` alone fails R8's own criterion.** R8 requires that classes 1, 8 and 13 still all
get caught. At `basename` they do not: the naive control's path claim `ledger/dunning.py`
survives, because `ledger/apps.yaml` spells `dunning` and not `dunning.py`. At
`basename+stem` all three classes are fully caught, on every SUT that reads them. That makes
`basename+stem` the **narrowest strategy satisfying R8's stated requirement**, which is a
sharper answer than "the default looks fine" and is checkable in one command.

**`+parent-dir` prevents the tenth false removal and destroys knip.** It is the only
strategy that reaches m02: `` await import(`./transports/${kind}Transport.js`) `` makes the
directory `transports` a contiguous literal in `src/index.ts` even though the specifier is
not, and §6.12's directory rule is exactly this. It is a real signal. Then look at the other
five blocks the same switch produced on the same tool — all six of knip's `blocked_claims`
at `+parent-dir`, laid out as `needle -> found_in` against the claim:

```
parent-dir 'transports' -> src/index.ts                          CLAIM src/transports/websocketTransport.ts
parent-dir 'src'        -> src/transports/websocketTransport.ts  CLAIM src/unusedAnalytics.ts
parent-dir 'src'        -> tests/cache.test.js                   CLAIM src/color_utils.js
parent-dir 'dist'       -> .gitignore                            CLAIM dist/widget.0c9e142.js
parent-dir 'dist'       -> .gitignore                            CLAIM dist/widget.7f3a91c.js
parent-dir 'src'        -> package.json                          CLAIM src/unusedFeatureFlags.ts
```

One correct rescue and five blocks on the words `src` and `dist`, two of them citing
`.gitignore` as evidence that build output is live. In the report they are indistinguishable:
same gate, same needle kind, same sentence shape. knip's fire rate goes to 100% and its decoy
recall to zero — the identical failure section 6 describes, arrived at by a different route. On the
naive control the same switch costs 8 decoys (26 → 18) and doubles the fire rate.

**The stem needle is free at this scale.** `basename` and `basename+stem` are identical on
all four real analyzers, and on the naive control the stem buys 4 more prevented false
removals (9 → 13) for zero additional decoys.

**What I would ship: `basename+stem`, which is what `DEFAULT_NEEDLES` already is.** The
sweep confirms the default rather than moving it. `basename` alone is dominated and fails
R8's own class-1/8/13 criterion. `+parent-dir` buys one true rescue at a price visible on
every SUT that claims paths, with a needle whose hits on `src` and `dist` no reader of the
output can tell apart from a real reference.

**R8 is not resolved here, and the reason is the corpus.** R8 asks for the fire rate
measured *on the E5 corpus* — a polyglot monorepo, a Django app, a plugin host, a vendored
tree, a repo with squashed history. This is E2: nineteen fixtures of a handful of files
each, written from the same document as the gate. A `parent-dir` needle on `src` blocks
everything in a fixture whose entire source tree is `src`; it would also block everything in
a monorepo, for a different reason and at a different rate. **The ranking of the three
distinct strategies is evidence. The percentages are not transferable.** R8's flag-rate half
remains open until E5 exists.

## 8. Limits

**This is in-sample.** Restated here because it is the largest limit and it belongs in the
list as well as at the top. The gate's rescue vocabulary and the catalogue derive from one
document. `ENUMERATION_CONSTRUCTS` contains `dir.glob`, `readdir` and `include_str!`; the
fixtures plant `dir.glob`, `readdir` and `include_str!`. A repository that enumerated a
directory with `pathlib.Path.iterdir()` — not on the list — would get no reachability rescue
at all, and nothing in this evaluation would have caught that.

**m13 has no reader.** Its live artifact is PHP rescued from a broad ignore rule by a `!`
negation, and no adapter here covers PHP. All four analyzers mark it *not read*, so this
round measures 18 of the 19 classes, exactly as the previous one did.

**Five of the six remaining false removals are out of Gate 2a's reach at any
configuration.** Section 3 names them. A whole-repo literal search rescues what is written down
twice and cannot rescue what is written down once — a ceiling set by the gate, not by its
settings — and the five are precisely the shapes §6.1 (structural reflection), §6.24 and
§6.9 (already-shipped and external consumers) identify as the hardest. The sixth, m02, is
reachable only through the directory needle, at the price section 7 measures.

**Four of vulture's seven rescues rest on a generic identifier.** `name` ×3 and `export`
×1 — collisions, not references. Section 4 shows the one that cost a decoy. It is visible here only
because the fixtures are small enough to read end to end; in a large repository *every*
common identifier collides, and the rate at which that happens is unmeasured.

**Fire rates measured on ten-file repositories do not extrapolate.** Section 7 states this
for the sweep and it applies to section 5's table too.

**Gate 2e (recency) is off, and would rescue everything if it were on.** Every fixture is
committed seconds before the analyzer runs, so any window covers every path. That is a fact
about the harness, not about 2e, and it means this document says nothing about what 2e is
worth.

**The reachability gate's cost is measured but not swept.** Six of the seven lost decoys
went to 2b/2c rather than to any needle. A sweep over `GateSet` would be a different
experiment; the axis R8 names is needles.

**The pickle result depends on scanning untracked-by-language bytes.** Gate 2a searches
every file `git ls-files` reports, including binaries, which is what rescues m16. The cost
is unmeasured here: a vendored blob or a large binary containing a common identifier vetoes
it everywhere.

**Gate 2a costs one full corpus read per candidate.** `LiteralVeto::query` documents the
batched shape it does not yet have, so its runtime on a monorepo is unknown.

**The superseded round's gated numbers cannot be re-derived from this build**, which is
what "superseded" means. The degenerate mechanism is still reachable in a unit test —
`veto_gate.rs::an_unattributed_decoy_symbol_is_rescued_by_its_own_declaration_and_that_is_the_documented_cost`
— but not from the command line, because the CLI now always passes the declaration site when
the analyzer gave one.

## 9. What this says about §11 R1, and what it does not

R1 asks whether an auto-act tier can exist at all, and pre-commits the consequence: if no
signal combination clears all classes at zero false removals, the tier is deleted from the
design rather than tuned.

**It says the earlier answer was to a different question.** Ten false removals from four
*bare* accusers is not evidence about signal combinations, because a bare accuser is not a
combination. §9.1's architecture is an analyzer orchestrated as a bounded accuser with a
veto behind it, and that is what this document measures.

**It does not discharge R1, and four things stand between it and that.**

*First, and sufficient on its own: no combination measured here clears the catalogue.* Six
false removals remain across four classes at the shipped configuration, five at the widest.
The pre-committed reading of that is not "tune the gate"; it is that this combination is not
an auto-act tier. cargo-shear+veto is the only combination at zero false removals that also
finds anything, it was already at zero before the veto, and the veto cost it four of nine
decoys — the veto contributing nothing to its safety and subtracting from its usefulness.
knip+veto also reaches zero, at `+parent-dir`, with 0 of 6 decoys: the refusing control with
extra steps.

*Second, the ones that remain are the ones that matter.* They are not near misses. Five of
the six are live artifacts named nowhere but their own declaration — a reflected field, a
convention-loaded class, an ABI export — and those are invisible to a literal search by
construction. Gate 2a is not a partial answer to them; it is the wrong instrument, and
§9.3's later gates or a different evidence family would have to carry them.

*Third, the catalogue measures 18 of 19, and it is in-sample.* A combination that clears 18
classes has not cleared the catalogue, and one graded on fixtures written from its own
specification has not been tested against a repository.

*Fourth, this is one veto implementation, one needle axis, four off-the-shelf analyzers at
their defaults.* §9.3 lists gates this build does not implement. R1 is a claim about *every*
signal combination, which no finite number of measured combinations can establish.

**What it does establish** is narrower and worth keeping: a veto layer moves the
false-removal count on real analyzers without being able to nominate anything, the movement
is attributable claim by claim to a named needle in a named file, and the price is
measurable in the same units as the benefit. Four prevented for seven decoys is a trade a
reader can argue with. That is the shape an answer to R1 would have to take, on a corpus
nobody wrote for it.
